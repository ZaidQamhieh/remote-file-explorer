## Findings

Severity scale: High = remote impact beyond the caller's grants; Medium = needs a grant or local precondition, real impact; Low = hardening or edge case.

### Confirmed by running

**F-01 Medium. Reading a FIFO inside a root hangs the request forever.**
- Cause: `ops.Open` does a blocking `open(O_RDONLY)` and no regular-file check (`agent/internal/fsops/jail.go:550-558`, used at `agent/internal/server/transferhandlers.go:57`). The share path already uses `O_NONBLOCK` (`share_handlers.go:208`).
- Repro (live): `mkfifo roots/fifo`; `GET /v1/content?path=roots/fifo`, `GET /v1/fs/checksum?path=...`, `POST /v1/fs/copy` with it as source: all three time out (curl 000 after 8 s); each leaks a goroutine and fd. Automated: `RFE_AUDIT_REPRO=1 go test ./internal/server -run DownloadFIFO` fails.
- Needs: a download/modify grant and a FIFO already in a root (any local user who can create one; also `/dev/zero`-style devices if a root covers `/dev`, which would also fill the disk on copy).
- Fix: open with `O_NONBLOCK`, `fstat`, reject non-regular files (400) in `Open`, checksum and `copySecureRecursive` (`fsops.go:1088`).

**F-02 Low. Share-link expiry cap bypass by integer overflow.**
- Cause: `time.Duration(req.ExpiresInSeconds)*time.Second > shareMaxExpiry` overflows (`share_handlers.go:79`).
- Repro: `POST /v1/share/mint {"path":..., "expiresInSeconds":18446744074}` returns 200 with `expiresAt` about 0.29 s out (test `TestAuditRepro_ShareExpiryOverflowRejected` fails). Other huge values wrap to values that may land inside 1 to 24 h or negative; a wrap to a negative value skips the cap too, so the lifetime is not bounded as documented.
- Fix: compare in seconds before multiplying: `req.ExpiresInSeconds > int64(shareMaxExpiry/time.Second)`.

**F-03 Low. Early `complete` destroys a resumable upload.**
- Cause: completing with a chunk missing returns 422 `HASH_MISMATCH` and marks the session terminal (`TRANSFER_NOT_OPEN` afterwards; the later chunk PUT returns 409).
- Repro (live): open a 5-chunk upload, PUT chunks 0-3, POST complete, then PUT chunk 4 returns 409 and complete returns 409.
- Impact: a client that completes early (bug, retry race) loses the whole upload. Wrong error code (should be a recoverable "chunks missing").
- Fix: check the received-chunk bitmap first and return 409/422 `CHUNKS_MISSING` without failing the session.

### Read from code, not reproduced

**F-04 Medium. Unbounded chunk buffering.** `transferhandlers.go:375-385` (`io.ReadAll` of up to 32 MiB per chunk) with no per-session or per-device concurrency cap (`transfer.go:243`). Many parallel PUTs from one upload-capable device cost about 32 MiB each. Fix: cap concurrent chunk writes or stream to the temp file.

**F-05 Medium. Compress can include its own partial archive.** `fsops/archive.go:70,132,141`: temp archive created in the walked tree. Fix: skip the temp and destination names, or reject destinations inside a source.

**F-06 Low. Single shared overflow bucket for the rate limiters** (`ratelimit.go:55-56`). With 4096 active keys, all new sources share 10 attempts/min, so an attacker with many source addresses can lock out legitimate pairing/login (denial of service, not bypass).

**F-07 Low. `/v1/register` burns an ordinary pairing code** (`register.go:81-91`): `Consume` runs before the `CanRegister` check.

**F-08 Low. Pair flow is not transactional** (`pair.go:87-120`): code consumed, then device upsert/reset/jail/read-only steps can fail separately, leaving a spent code, or a device paired without the guest jail/read-only flags if `SetDeviceJail`/`SetDeviceReadOnly` fail after the upsert (the failure returns 500 but the token row exists). Worth a test: guest pairing with an injected DB error.

**F-09 Low. Brute-force limits are per source IP only** (`login.go`, `pair.go`, `challenge.go`). No per-account lockout; many source addresses multiply the guess rate. Pairing codes are 8 chars of a 32-letter alphabet (40 bits), so it is impractical for pairing; matters for owner passwords.

**F-10 Low. Share mint stats the raw path, not the resolved path** (`share_handlers.go:85,90`): TOCTOU between `Resolve` and `Stat`.

**F-11 Low. Web logout clears the cookie but does not revoke the token** (`pair.go:62-65`).

**F-12 Low. Sidecar request ids can collide** (`rfe-indexd/src/server.rs:120,137`, `rfe-thumbd/src/server.rs:229,90`): a duplicate in-flight id overwrites and then removes another job's cancel flag. The Go client numbers requests itself, so this needs a client bug. `rfe-indexd` also spawns one thread per request without a cap (`server.rs:115-123`).

**F-13 Medium (supply chain). Updates carry no signature.** Desktop `updates.rs:359-362,426` and phone `updateLogic.ts:9,18`, `updateService.ts:97`: the checksum comes from the same release as the package. Android's same-signer rule limits the phone impact; the desktop installs whatever the release holds. Fix: sign `SHA256SUMS` (minisign/ed25519 key pinned in the app).

**F-14 Low. Desktop `local.rs:227-230`**: existence check then `rename`, which overwrites on Unix if the target appears in between. Use `renameat2(RENAME_NOREPLACE)` or `hard_link` + unlink.

**F-15 Low. mDNS flooding hides the real agent** (`desktop/.../discovery.rs:107-127`): results are capped by name order, so 50 spoofed instances pushing the real one out is possible. Trust is unaffected (pinning decides).

### Phone app (read only)

**F-16 Medium. Media proxy leak** (`MediaViewers.tsx:40-51`, `MediaProxy.kt:113-124`): leaving a video before `clientForHost` resolves leaves a 127.0.0.1 listener, thread pool and bearer headers alive.

**F-17 Medium. Forgetting a host does not purge file content** (`services.ts:33-36`): preview, thumbnail, PDF page and open/share caches keep the host's bytes after unpair/revoke (`previewFile.ts:38,69`, `thumbnails.ts:34`, `PdfViewer.tsx:23`, `externalFiles.ts:28`).

**F-18 Medium. Share-sheet file names are not sanitized** (`shareLogic.ts:12`, `enqueueUploads.ts:25-27`): a name containing `../` is used for the staged file and joined into the remote path (`joinRemotePath(destDir, targetName)`), so it can leave the chosen folder (still inside the device jail) and the staging dir. Android normally passes a base name, so exploiting it needs a malicious sending app. `safeFileName` already exists in `externalFiles.ts`. Plausible.

**F-19 Medium (design decision). App lock fails open** when the biometric prompt is `unavailable` (`lockLogic.ts:18`, tested as intended in `lockLogic.test.ts:22`): removing the screen lock or an exception from `authenticateAsync` unlocks the app. Documented as a deliberate parity choice; the owner should confirm it.

**F-20 Medium. Photo backup runs can overlap** (`photoBackupService.ts:57-136`, `backgroundTask.ts:33`, `photo-backup.tsx:120`): no in-flight lock, so the background task and "Back up now" can enqueue the same upload id twice (`TransferEngine.kt:135` overwrites the record). Plausible.

**F-21 Low.** `enqueueUploads.ts:11,26-27`, `enqueueDownloads.ts:24`: `decodeURIComponent` can throw on `%` in names after the file was moved (orphan staged copy). `TransferEngine.kt:292`: size check skipped for chunked downloads (-1 length) and downloads have no hash check. `PublicHttp.kt:26-28`: redirects to `http://` are followed (SHA-256 still checked for the APK). `agentClient.ts:219-225`: 2xx with malformed JSON becomes `null`. `log.ts:9`: redactor misses `deviceToken` by pattern. `TransferEngine.kt:151-165`: cancel deletes the upload source while a worker may read it.

**F-22 Low (live).** Uploaded files are created mode 0600 (live: `-rw-------` after a chunked upload), ignoring the umask; other local users and services on the PC cannot read them.

**F-23 Low. Offline cache restore deletes a valid body on any IOException** (`OfflineBodyStore.kt:63-66`), including ENOSPC while writing. Delete only on an authentication failure.

**F-24 Low.** `FetchFile.kt:50` removes the call by id unconditionally (a newer fetch with the same id loses its cancel handle); `FetchFile.kt:21,38` `maxBytes` defaults to 0 = unbounded for thumbnails.

**F-25 Low. Device signature has no domain or host binding** (`deviceIdentity.ts:93-95`, preflight `agentClient.ts:322`): the agent requires the v2 bound proof when pairing, so impact is limited to the browser sign-in path; trace the call sites before fixing.

Still unread: `features/pairing`, `hosts`, `handoff`, `sync`, `backup` TypeScript, `Uploader.kt` 1-43, `TransferEngine.kt` 1-131, `TransferService.kt`.

### Desktop and sidecars, second pass

**F-26 Low (latent). thumbd `render.rs:111`** casts `ow`/`oh` to `u16`, so a source wider than 65535 with `max` above 65535 would be encoded at a wrong width. Not reachable through the agent: `thumb.go` clamps `size` to `maxThumbSize` (checked). Add a clamp in thumbd too.

**F-27 Low. Desktop upload source can change after the session opens** (`transfers.rs:534,1626,1769-1785`): identity is checked at enqueue and resume only; the whole-file hash is taken at open, so an edit mid-upload fails only at completion (agent rejects it with HASH_MISMATCH, as in F-03's path). Wasteful, not unsafe.

Clean: no XSS in `ui.js`, `fx3.js`, `fx5.js`, `pages.js`, `fpages.js`, `fx6.js` (every interpolation goes through `esc`/`hl`); `icons.js:125` interpolates an unescaped icon name but every caller passes a literal; thumbd seccomp allowlist has no bypass (no open/openat, clone limited to thread flags, RLIMIT_FSIZE 0). Still unread: `files.rs` 428-660, `fileops.rs` 830-930, `fx2.js:91`, `fx6.js:168`, `features.js:120,294`, `fx4.js:54`.

### Phone, third pass (read only; timing needs a run)

**F-28 Medium. A forgotten computer can come back.** `hostStore.ts:62-65` (`updateHost` calls `addHost` when the id is missing) with `useHostStatus.ts:55,62,65`: a health ping that started before "forget" writes its old snapshot back, re-adding the host (without secrets) and its `lastSeen`. Fix: `updateHost` must not add; the ping must check the host still exists.

**F-29 Medium. Ping overwrites concurrent host edits.** `useHostStatus.ts:55,62` writes the whole host object it captured; `hostStore.ts:62-68,92-108` read-modify-write has no lock. Editing an address or label during a ping reverts it. Fix: per-store mutex plus partial updates of the learned fields only.

**F-30 Low. `requestPairing` (approve-on-PC) skips `checkKnownPin`** (`pairingService.ts:204-209` vs `:88-92,:135`); a different certificate at an already-saved address overwrites the stored pin on commit (`hostStore.ts:81`). Protection rests on the owner's approval and match code. Fix: call `checkKnownPin` there too.

**F-31 Low. Sync staging path from a server entry name** (`syncService.ts:81-84`): a listed entry named `..` makes `discard` delete the sync cache directory's contents. Reject names that are not one path segment.

Clean: secrets-first commit with rollback, `checkKnownPin` blocks sending a password on pin mismatch, pin read from secure store. Still unread: `features/handoff`, `backup`, `offline` TS, host-settings UI, `pair/scan.tsx`, `TransferEngine.kt` 1-131, `Uploader.kt` 1-43, `TransferService.kt`.
